v0.2.3 问题修复：修复 0.2.2 牌桌顶栏不显示阶段（如「等待开局 30s」）与余额胶囊；顶栏胶囊自动让开顶部座位头像，空间不足时局数与阶段胶囊同比例缩小字号，返回按钮大小不变并保持垂直居中。公共 API 无变更，使用 0.2.2 的宿主建议尽快升级。

v0.2.2 新功能：牌桌按竖屏设计稿重新布局：竖屏内嵌时头像、名字、手牌、「立即加入」与底注放大并居中，全屏后沿用同一布局按屏幕等比放大，与 H5 SDK 0.2.2 一致；修复嵌入模式调用 [CocosGameSDK.shared close] 后闪退，任何时机关闭都安全；新增事件名常量 CocosGameEventLoginRequired、CocosGameEventWalletBalanceChanged 与 action 取值 CocosGameLoginActionJoin / CocosGameLoginActionRecords / CocosGameLoginActionFullscreen（Swift 同名）；修复观战状态切换时 gameSDKDidChangePlayingState:NO 可能连续回调两次；引擎按体积优化编译，压缩包 24.90 MB → 23.90 MB。公共 API 无变更，升级版本即可。

v0.2.1 新功能：新增游客观战（仅直播间，群聊必须登录），通过 initGuestWithWebsocketURL:apiBaseURL:deviceId:sceneId:…CocosGameSessionConfig(guestWithWebsocketURL:apiBaseURL:deviceId:sceneId:…) 创建游客会话。游客只能观战，牌桌不显示余额，下注阶段不弹下注窗；入座、查看记录、全屏时发送通用事件 auth.login_required，由宿主提示登录，详见 游客观战。老接入无需修改。

v0.2.0 新功能：竖屏下注、记录与规则、退出确认统一可由宿主自绘，全屏仍由游戏内弹窗展示。宿主实现可选回调 gameSDKDidReceiveBetOptions:gameId:gameSDKDidReceiveBetOptions(_:gameId:) / gameSDKDidRequestShowRecords:gameId:gameSDKDidRequestShowRecords(_:gameId:) 即接管，并通过 submitBetWithRoundId:…submitBet(roundId:…)、queryRecordsIsHistory:…queryRecords(isHistory:…) 下注与查询；未实现时沿用 SDK 自带界面，老接入无需修改。新增钱包余额事件 wallet.balance_changed。全屏时退出座位改为游戏内确认框。

v0.1.11 新功能：新增迷你条，宿主把游戏容器缩成 362:50 横条后调用 setMiniMode:backgroundColorHex:setMiniMode(_:backgroundColorHex:)；新增可选回调 gameSDKDidRequestExpand；修复宿主调整嵌入容器尺寸后画面拉伸。迷你条为可选功能，其余公共 API 无变更。

v0.1.10 优化与修复：游戏包体精简（xcframework 压缩包 32.2MB → 24.9MB），修复有头像的玩家在等待阶段头像闪烁，记录搜索框光标垂直居中。公共 API 无变更，宿主只需升级版本。

v0.1.9 首个 iOS 版本：同一个 xcframework 同时支持 Objective-C 与 Swift，Swift 直接 import CocosGameSDK，无需桥接头文件；功能与 Android SDK 0.1.9 对齐，牛牛牌桌在宿主页面容器内嵌展示，支持全屏切换；竖屏下「记录与规则」底部弹窗与加注筹码卡片为原生实现，样式与 Android 一致；游戏展示期间静音键开启也能正常播放声音。

接入前准备

  • 宿主客户端完成用户登录并获得 liveUserId、imUserId、liveToken。
  • 宿主动态传入 sceneType：1 直播间，2 IM 群。
  • 宿主动态传入 sceneId，SDK 不内置固定场景。
  • 正式环境必须使用 HTTPS/WSS，无需配置 ATS 例外。

5 分钟快速接入

  1. 通过 SPM 或 CocoaPods 添加 CocosGameSDK 0.2.3。
  2. 主窗口创建后调用 initializeWithWindow:launchOptions:initialize(window:launchOptions:)。
  3. 客户端登录后创建 CocosGameSessionConfig。
  4. 提供游戏容器视图，调用 openGame:sessionConfig:inContainer:fromViewController:openGame(_:sessionConfig:container:viewController:)。
  5. 离开页面时调用 closeclose()。
#import <CocosGameSDK/CocosGameSDK.h>

[[CocosGameSDK shared] initializeWithWindow:self.window launchOptions:launchOptions];

[CocosGameSDK shared].delegate = self;
[[CocosGameSDK shared] openGame:@"niuniu"
                  sessionConfig:sessionConfig
                    inContainer:self.gameContainer
             fromViewController:self];
import CocosGameSDK

CocosGameSDK.shared.initialize(window: window, launchOptions: launchOptions)

CocosGameSDK.shared.delegate = self
CocosGameSDK.shared.openGame("niuniu",
                             sessionConfig: sessionConfig,
                             container: gameContainer,
                             viewController: self)

初始化 SDK

在宿主主窗口创建后初始化一次。

使用 AppDelegate 窗口的宿主在 application:didFinishLaunchingWithOptions: 中调用；使用 SceneDelegate 的宿主在 scene:willConnectToSession:options: 中创建窗口后调用，launchOptions 传 nil。

按宿主工程类型三选一：AppDelegate 窗口、SceneDelegate（Xcode UIKit 模板默认）、SwiftUI（见下方「SwiftUI 接入」）。SceneDelegate 与 SwiftUI 中 launchOptions 传 nil。

SceneDelegate

func scene(_ scene: UIScene, willConnectTo session: UISceneSession,
           options connectionOptions: UIScene.ConnectionOptions) {
    guard let windowScene = scene as? UIWindowScene else { return }
    let window = UIWindow(windowScene: windowScene)
    window.rootViewController = rootViewController
    CocosGameSDK.shared.initialize(window: window, launchOptions: nil)
    window.makeKeyAndVisible()
    self.window = window
}

AppDelegate

SwiftUI 接入

SwiftUI 宿主用 UIViewControllerRepresentable 承载游戏页。SwiftUI 没有 AppDelegate 窗口，在承载页显示后用其所在窗口初始化；视图移除时关闭游戏。

final class GameHostViewController: UIViewController, CocosGameSDKDelegate {
    let gameContainer = UIView()
    let sessionConfig: CocosGameSessionConfig
    private var hasOpened = false

    init(sessionConfig: CocosGameSessionConfig) {
        self.sessionConfig = sessionConfig
        super.init(nibName: nil, bundle: nil)
    }

    required init?(coder: NSCoder) { nil }

    override func viewDidLoad() {
        super.viewDidLoad()
        gameContainer.translatesAutoresizingMaskIntoConstraints = false
        view.addSubview(gameContainer)
        NSLayoutConstraint.activate([
            gameContainer.topAnchor.constraint(equalTo: view.safeAreaLayoutGuide.topAnchor),
            gameContainer.leadingAnchor.constraint(equalTo: view.leadingAnchor),
            gameContainer.trailingAnchor.constraint(equalTo: view.trailingAnchor),
            gameContainer.heightAnchor.constraint(equalTo: gameContainer.widthAnchor, multiplier: 211.0 / 375.0),
        ])
    }

    override func viewDidAppear(_ animated: Bool) {
        super.viewDidAppear(animated)
        guard !hasOpened else { return }
        hasOpened = true
        // SwiftUI 宿主没有 AppDelegate 窗口，用承载页所在窗口初始化
        if let window = view.window { CocosGameSDK.shared.initialize(window: window, launchOptions: nil) }
        CocosGameSDK.shared.delegate = self
        view.layoutIfNeeded()
        CocosGameSDK.shared.openGame("niuniu", sessionConfig: sessionConfig,
                                     container: gameContainer, viewController: self)
    }

    func gameSDKDidChangeState(_ state: CocosGameSDKState) {}
    func gameSDKDidFail(error: Error) { print("游戏失败：\(error.localizedDescription)") }
    func gameSDKDidRequestExit(completion: @escaping (Bool) -> Void) { completion(true) }
    func gameSDKDidChangePlayingState(_ isPlaying: Bool) {}
}

struct GameView: UIViewControllerRepresentable {
    let sessionConfig: CocosGameSessionConfig

    func makeUIViewController(context: Context) -> GameHostViewController {
        GameHostViewController(sessionConfig: sessionConfig)
    }

    func updateUIViewController(_ viewController: GameHostViewController, context: Context) {}

    static func dismantleUIViewController(_ viewController: GameHostViewController, coordinator: ()) {
        CocosGameSDK.shared.close()
    }
}

// 使用
GameView(sessionConfig: sessionConfig)

代理回调

宿主实现 CocosGameSDKDelegate，delegate 为弱引用。

Objective-CSwift必选说明
gameSDKDidChangeState:gameSDKDidChangeState(_:)是SDK 状态变化
gameSDKDidFailWithError:gameSDKDidFail(error:)是SDK 失败及上下文
gameSDKDidRequestExitWithCompletion:gameSDKDidRequestExit(completion:)是竖屏时游戏中请求离开座位（全屏由游戏内确认框处理，不回调），宿主弹确认框后回调 completion(YES/NO)completion(true/false)
gameSDKDidChangePlayingState:gameSDKDidChangePlayingState(_:)是是否参与座位游戏
gameSDKDidRequestBackgameSDKDidRequestBack()否牌桌返回箭头；实现后宿主自行 close 并关闭页面，未实现时 SDK 直接 close
gameSDKDidRequestExpandgameSDKDidRequestExpand()否迷你条展开按钮；实现后宿主恢复容器尺寸并调用 setMiniMode 传 NO，未实现时 SDK 直接退出迷你模式
gameSDKDidInvalidateSessionWithMessage:gameSDKDidInvalidateSession(message:)否Token 失效等，SDK 已关闭游戏，宿主应清理凭据并回登录页
gameSDKDidReceiveEvent:payloadJSON:gameId:gameSDKDidReceiveEvent(_:payloadJSON:gameId:)否游戏发出的通用业务事件
gameSDKDidUpdateGame:… / gameSDKDidFailUpdateGame:…gameSDKDidUpdateGame(_:…) / gameSDKDidFailUpdateGame(_:…)否模块更新进度与失败
gameSDKDidReceiveBetOptions:gameId:gameSDKDidReceiveBetOptions(_:gameId:)否竖屏本局开始下注；实现即接管竖屏下注界面，见「竖屏宿主自绘」
gameSDKDidCloseBetRound:gameId:gameSDKDidCloseBetRound(_:gameId:)否本局下注截止（倒计时结束、离局或切到全屏）
gameSDKDidReceiveBetResult:gameId:gameSDKDidReceiveBetResult(_:gameId:)否下注结果，按 clientBetNo 对应
gameSDKDidRequestShowRecords:gameId:gameSDKDidRequestShowRecords(_:gameId:)否竖屏点击记录与规则；实现即接管竖屏记录弹窗
gameSDKDidUpdateRecords:gameId:gameSDKDidUpdateRecords(_:gameId:)否记录完整快照更新，整体替换即可

SDK API 需在主线程调用；所有回调都在主线程触发，可直接更新 UI。

退出确认示例

- (void)gameSDKDidRequestExitWithCompletion:(void (^)(BOOL))completion {
    UIAlertController *alert = [UIAlertController alertControllerWithTitle:@"退出游戏？"
        message:@"当前游戏正在进行中，离开后游戏将结束并结算。"
        preferredStyle:UIAlertControllerStyleAlert];
    [alert addAction:[UIAlertAction actionWithTitle:@"离开" style:UIAlertActionStyleDestructive
        handler:^(UIAlertAction *action) { completion(YES); }]];
    [alert addAction:[UIAlertAction actionWithTitle:@"取消" style:UIAlertActionStyleCancel
        handler:^(UIAlertAction *action) { completion(NO); }]];
    [self presentViewController:alert animated:YES completion:nil];
}
func gameSDKDidRequestExit(completion: @escaping (Bool) -> Void) {
    let alert = UIAlertController(title: "退出游戏？",
                                  message: "当前游戏正在进行中，离开后游戏将结束并结算。",
                                  preferredStyle: .alert)
    alert.addAction(UIAlertAction(title: "离开", style: .destructive) { _ in completion(true) })
    alert.addAction(UIAlertAction(title: "取消", style: .cancel) { _ in completion(false) })
    present(alert, animated: true)
}

通用事件

接收游戏事件

- (void)gameSDKDidReceiveEvent:(NSString *)event
                   payloadJSON:(NSString *)payloadJSON
                        gameId:(NSString *)gameId {
    if ([event isEqualToString:@"niuniu.wallet.open"]) [self openWalletPage];
}
func gameSDKDidReceiveEvent(_ event: String, payloadJSON: String, gameId: String) {
    if event == "niuniu.wallet.open" { openWalletPage() }
}

向游戏发送事件

[[CocosGameSDK shared] sendGameEvent:@"niuniu.wallet.closed"
                         payloadJSON:@"{\"isBalanceChanged\":true}"];
CocosGameSDK.shared.sendGameEvent("niuniu.wallet.closed",
                                  payloadJSON: #"{"isBalanceChanged":true}"#)
  • 事件名必须匹配 ^[a-z][a-z0-9_.-]{0,63}$，建议带模块前缀。
  • 载荷必须是 JSON 对象字符串或 nil。
  • Token、密码等敏感数据不得放入通用事件。

CocosGameSessionConfig 参数

参数规则
websocketURL必须为 wss://
apiBaseURL必须为 https://
liveUserId客户端登录后的直播 UID（登录响应 uid），用于大厅鉴权，大于 0
imUserId客户端登录后的 IM UID（登录响应 userinfo.imUserId），用于识别本人座位，大于 0
liveToken客户端登录后的有效 Token
deviceId仅游客会话：宿主生成的稳定设备标识，1~128 个字符，不含空白与控制字符，原样使用
sceneTypeCocosGameSceneTypeLiveRoom.liveRoom（1 直播间）或 CocosGameSceneTypeIMGroup.imGroup（2 IM 群）
sceneId客户端当前场景 ID，按字符串原样传入，不允许为空
tableId0 自动选择，正整数指定桌台
clientVersion宿主客户端版本
deviceTypeiOS

参数不合法时 Objective-C 初始化返回 nil 并通过 error 给出原因，Swift 中初始化抛出错误；此时不应继续打开游戏。

客户端与 SDK 职责

客户端负责

  • 账号登录、Token 刷新和退出。
  • UID、Token、Scene Type、Scene ID。
  • 提供游戏容器视图与页面导航。
  • 退出确认框、返回离开处理。
  • 会话失效后返回登录流程。
  • 自定义钱包、充值或其他业务页面。

SDK 负责

  • 游戏引擎挂载与内置资源加载。
  • 大厅 HTTP、WebSocket、重连和快照恢复。
  • 游戏音频和生命周期。
  • 入座、下注、结算与界面状态。
  • 内嵌与全屏切换、等比适配。
  • 记录与规则、下注卡片与通用事件桥。

全屏、弹窗与生命周期

  • 全屏时 SDK 将游戏视图旋转 90° 铺满屏幕，宿主页面保持竖屏，无需在 Info.plist 中开启横屏。
  • 不要修改游戏容器的 transform，也不要在全屏期间改动容器约束。
  • 竖屏内嵌时，未接管的「记录与规则」以 SDK 底部弹窗展示，下注阶段在游戏容器下方展示 SDK 加注筹码卡片（覆盖在宿主内容上，下注或倒计时结束后自动收起）；宿主可接管自绘，见「竖屏宿主自绘」。全屏时下注、记录与退出确认都在牌桌内展示。
  • 进入后台时 SDK 暂停音频和实时连接；回前台重新认证并拉取权威桌态后恢复交互。
  • 游戏展示期间 SDK 使用 Playback 音频会话（与其他音频混音），关闭游戏后恢复。
  • App 被强杀时，座位释放依赖服务端断线自动离座。

我的记录

「我的记录」由 SDK 内置实现，客户端无需调用任何 API、无需注册回调。用户在游戏内点击「规则」按钮，切换到「我的记录」页签即可查看本人注单。

  • SDK 使用 CocosGameSessionConfig 中的 apiBaseURL、liveUserId、liveToken 请求后台，与入座、下注接口相同。
  • 当前本桌：POST /api/lobby/bet/table/mine；历史场次：POST /api/lobby/bet/history。
  • 每页 20 条，滑到底部自动加载下一页；失败显示点击重试，无数据显示空状态。

迷你条

宿主可把牌桌缩成 362:50 的横条，下方宿主内容随之上移。容器尺寸由宿主控制：先切换容器约束，再调用 SDK；SDK 同步渲染尺寸后通知牌桌切换为迷你条。

  • 迷你条显示局数、阶段、头像、手牌与结算输赢、余额、展开和退出按钮；入座显示自己，旁观显示庄家，无庄家显示问号头像。
  • backgroundColorHex 为容器所在页面底色（#RRGGBB），用于迷你条圆角外区域，传 nil 为白色。
  • 玩家点击展开按钮时回调 gameSDKDidRequestExpand，宿主恢复容器约束后退出迷你模式。
  • 退出按钮与牌桌返回按钮行为一致；迷你模式下不可切换全屏。
// 缩小
[NSLayoutConstraint deactivateConstraints:self.embeddedConstraints];
[NSLayoutConstraint activateConstraints:self.miniConstraints];
[self.view layoutIfNeeded];
[[CocosGameSDK shared] setMiniMode:YES backgroundColorHex:@"#FFFFFF"];

// 玩家点击迷你条展开按钮
- (void)gameSDKDidRequestExpand {
    [NSLayoutConstraint deactivateConstraints:self.miniConstraints];
    [NSLayoutConstraint activateConstraints:self.embeddedConstraints];
    [self.view layoutIfNeeded];
    [[CocosGameSDK shared] setMiniMode:NO backgroundColorHex:nil];
}
// 缩小
NSLayoutConstraint.deactivate(embeddedConstraints)
NSLayoutConstraint.activate(miniConstraints)
view.layoutIfNeeded()
CocosGameSDK.shared.setMiniMode(true, backgroundColorHex: "#FFFFFF")

// 玩家点击迷你条展开按钮
func gameSDKDidRequestExpand() {
    NSLayoutConstraint.deactivate(miniConstraints)
    NSLayoutConstraint.activate(embeddedConstraints)
    view.layoutIfNeeded()
    CocosGameSDK.shared.setMiniMode(false, backgroundColorHex: nil)
}

交互时序

以下回调仅在手机竖屏内嵌（非全屏）时触发，全屏时由游戏内弹窗展示；游戏进入全屏（isFullscreen 为 YES）时，建议宿主收起自绘的下注和记录面板。游客不会触发下注与记录回调，改为发送 auth.login_required。

时机SDK / 宿主调用宿主处理
进入下注阶段（每局一次）回调 gameSDKDidReceiveBetOptions:gameId:gameSDKDidReceiveBetOptions(_:gameId:)显示下注面板：注区、筹码、倒计时
玩家选注区和筹码宿主调用 submitBetWithRoundId:…submitBet(roundId:…)结果经 gameSDKDidReceiveBetResult:gameId:gameSDKDidReceiveBetResult(_:gameId:) 返回，按 clientBetNo 对应
下注截止或离局回调 gameSDKDidCloseBetRound:gameId:gameSDKDidCloseBetRound(_:gameId:)收起下注面板
玩家点击记录与规则回调 gameSDKDidRequestShowRecords:gameId:gameSDKDidRequestShowRecords(_:gameId:)打开记录面板，首屏数据在 records 字段
切换本桌 / 历史、筛选、搜索宿主调用 queryRecordsIsHistory:filterKey:periodIndex:keyword:queryRecords(isHistory:filterKey:periodIndex:keyword:)先回调 gameSDKDidUpdateRecords:gameId:gameSDKDidUpdateRecords(_:gameId:)（list.status 为 loading），查询完成再回调一次
滑到列表底部宿主调用 loadMoreRecordsIsHistory:loadMoreRecords(isHistory:)结果经 gameSDKDidUpdateRecords:gameId:gameSDKDidUpdateRecords(_:gameId:) 返回，整份替换即可
关闭记录面板无需通知游戏宿主自行关闭

记录数据字段

展示记录回调与记录更新回调的 JSON 由游戏统一生成，三端一致；文案均已本地化，宿主直接展示即可。

字段说明
title / roomTag规则标题、房间标签（仅展示记录回调）
sections[]规则分组：title、items[]（title、value、description）（仅展示记录回调）
records首屏记录，结构同下（仅展示记录回调；记录更新回调直接是这份结构）
currentTab / historyTab「本桌」「历史」页签文字
filters[]下注类型筛选 { key, label }，全部为 all；查询时传 filterKey
current.items[]本桌每局：title、detail、result、tone、type
current.banner / stats[]本桌提示条、统计项 { label, value, tone }
history.sessions[]历史场次：key、title、amount、tone、detail、source、daysAgo、types[]、rounds[]（结构同 current.items）
history.periods[]时间范围 { label, days }，查询时传下标 periodIndex
history.sources[] / searchPlaceholder / searchButton来源列表、搜索框占位与按钮文字
current.list / history.list列表状态：status（loading / ready / error）、hasMore、isLoadingMore、message（错误信息）

游客观战（仅直播间）

未登录用户可以游客身份进入直播间观战，群聊必须登录。游客只能观战：牌桌不显示右上角余额，下注阶段不弹下注窗，也不通知宿主。

auth.login_required 载荷触发操作
{"action":"join"}点击立即加入
{"action":"records"}点击记录与规则
{"action":"fullscreen"}点击全屏（旋转大屏），不会进入全屏
  • 需要登录的操作统一通过 gameSDKDidReceiveEvent:payloadJSON:gameId:gameSDKDidReceiveEvent(_:payloadJSON:gameId:) 发送 auth.login_required，游戏内不弹提示，由宿主提示登录。

常见问题

打开后黑屏

确认已调用 initializeWithWindow:launchOptions:initialize(window:launchOptions:)，容器视图在 openGame 前已完成布局且尺寸不为 0。Rosetta 模拟器首次启动较慢，等待 30 秒左右。

模拟器提示架构不匹配

当前模拟器切片只有 x86_64。在 Apple Silicon 上选择 Rosetta 模拟器，或在 Build Settings 中设置 EXCLUDED_ARCHS[sdk=iphonesimulator*] = arm64。

启动崩溃提示找不到 CocosGameSDK.framework

本地集成时确认设置为 Embed & Sign，而不是 Do Not Embed。

WebSocket 一直认证失败

确认 liveUserId 与 liveToken 匹配、未过期，HTTP 与 WebSocket 属于同一环境。

大厅没有可用桌

确认 Scene Type、Scene ID 与后台开桌场景一致，指定的 tableId 仍有效。

上线验收清单

  • SDK 只初始化一次，打开前已设置 delegate。
  • UID、Token、Scene Type、Scene ID 均来自客户端。
  • 能进入牛牛桌并收到实时阶段。
  • 入座、离座、下注和结算正常。
  • 记录与规则、下注卡片、退出确认关闭后按钮仍可点击。
  • 接管竖屏下注 / 记录时：宿主界面能下注并看到结果；切全屏后宿主下注界面收起，改由游戏内弹窗展示。
  • 小屏、大屏往返后全部按钮仍可点击。
  • 返回箭头离开、再次进入游戏正常。
  • 进入后台再返回能够恢复桌态。
  • Token 失效后能返回客户端登录流程。
  • iOS 16 与当前主流系统真机至少各完成一次冒烟测试。
  • 未记录 Token、密码或完整敏感响应。
